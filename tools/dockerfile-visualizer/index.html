Dockerfile Visualizer

Paste a Dockerfile and watch it become a build-pipeline graph: each stage is a column, each instruction a node, and COPY --from dependencies are drawn as edges between stages. Nodes are heat-mapped by layer-cache volatility — green layers survive a typical code change, red layers rebuild on almost every one — and the linter flags unpinned base images, root containers, cache breakers and mergeable RUN layers as you type.

How to read the graph

Each dashed box is a build stage (one per FROM); the nodes inside are its instructions, top to bottom in build order. Hover any node for the full instruction and its findings.

  • Cache heatmap — Docker caches layers sequentially, so once one layer changes, everything below it rebuilds. Green nodes sit above the first volatile layer and stay cached; red nodes rebuild on almost every source change. A classic fix: copy dependency manifests (package.json, go.mod…) and install before the broad COPY . ..
  • Edges — solid arrows are artifacts flowing between stages (COPY --from, RUN --mount=from=…); dashed arrows mean a stage builds on another stage as its base image.
  • Badges — a red ! marks a warning (unpinned :latest, running as root, cache breakers, secrets in ENV/ARG); an amber one marks a suggestion.
  • Dashed amber groups — adjacent RUN instructions that each create a layer; merge them with && to ship one smaller layer.

Everything runs locally in your browser — your Dockerfile never leaves the page.
